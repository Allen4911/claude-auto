# 03-6. Git Worktree로 병렬 개발

여러 서브에이전트가 동시에 파일을 수정하면 충돌합니다. 에이전트 A가 `src/auth.ts`를 편집하는 동안 에이전트 B가 같은 파일에 손대면 한쪽이 다른 쪽 작업을 덮어씁니다. Claude Code는 이 문제를 git 워크트리(worktree)로 해결합니다. 에이전트마다 독립된 작업 공간을 배정해 충돌 자체를 막습니다.

## Git Worktree 개념과 셋업

### 워크트리란

git 워크트리는 하나의 `.git` 저장소에서 여러 브랜치를 동시에 다른 디렉토리에 체크아웃할 수 있는 git 기본 기능입니다. `git worktree add` 명령으로 새 디렉토리를 만들면 별도 작업 공간이 생깁니다. 이 작업 공간은 `.git` 이력과 리모트를 원본과 공유하되 브랜치는 따로 씁니다.

```bash
# 수동으로 워크트리 생성 예시
git worktree add ../project-feature-auth -b feature-auth
```

이렇게 하면 `../project-feature-auth` 디렉토리가 생기고 거기서 `feature-auth` 브랜치로 독립적으로 작업할 수 있습니다. 메인 체크아웃과 파일 충돌 없이 두 브랜치를 동시에 열어 둘 수 있습니다.

### Claude Code에서 워크트리를 사용하는 3가지 방식

Claude Code는 이 git 기능을 세 가지 형태로 활용합니다.

**A. `--worktree` 플래그 — 대화형 병렬 세션**

```bash
claude --worktree feature-auth
```

`.claude/worktrees/feature-auth/` 아래 `worktree-feature-auth` 브랜치로 워크트리가 생성됩니다. 이름을 생략하면 `bright-running-fox` 같은 이름을 자동으로 붙여 줍니다.

PR에서 직접 분기할 수도 있습니다.
```bash
claude --worktree "#1234"
```

**B. Agent View — 백그라운드 세션 자동 격리**

`claude agents`로 에이전트 팀을 사용할 때, 파일 편집을 시작하는 모든 백그라운드 세션이 자동으로 `.claude/worktrees/` 아래 워크트리로 이동합니다. 별도 플래그가 필요 없습니다.

비활성화가 필요하다면:
```json
{
  "worktree": {
    "bgIsolation": "none"
  }
}
```

**C. 데스크톱 앱**

모든 새 세션에 자동으로 자체 워크트리가 배정됩니다.

### 프로젝트 초기 설정

워크트리 기능을 프로젝트에서 깔끔하게 사용하려면 세 가지를 설정합니다.

**Step 1: .gitignore에 워크트리 디렉토리 추가**
```
.claude/worktrees/
```

**Step 2: .worktreeinclude 파일 작성**

프로젝트 루트에 `.worktreeinclude` 파일을 만들면 새로 만드는 워크트리에 `.gitignore` 대상 파일(`.env`, 시크릿 등)이 자동으로 복사됩니다. 트래킹되는 파일은 git으로 공유되므로 복사하지 않습니다.

```
# .worktreeinclude
.env
.env.local
config/secrets.json
```

이 설정은 `--worktree` 워크트리, `isolation: worktree` 서브에이전트, 데스크톱 병렬 세션 모두에 적용됩니다.

**Step 3: 베이스 브랜치 설정 (선택)**

워크트리가 어느 지점에서 분기할지 결정합니다.

```json
{
  "worktree": {
    "baseRef": "head"
  }
}
```

| 값 | 분기 시작점 |
|---|---|
| `"fresh"` (기본값) | 원격 기본 브랜치(`origin/HEAD`, 보통 `main`) |
| `"head"` | 현재 로컬 HEAD (미푸시 커밋·피처 브랜치 포함) |

> ⚠️ **주의**: 기본값 `"fresh"`는 원격 `main`에서 분기합니다. 현재 피처 브랜치 위에서 작업 중이라면 `"head"`로 설정해야 미푸시 커밋이 포함됩니다. 브랜치명을 직접 지정할 수는 없습니다(`"fresh"`/`"head"` 두 값만 유효).

## 서브에이전트별 독립 작업공간

### isolation: worktree 프론트매터

서브에이전트 정의 파일에 `isolation: worktree`를 설정하면 해당 서브에이전트가 호출될 때마다 임시 워크트리에서 실행됩니다.

```markdown
---
name: refactorer
description: 여러 파일에 걸친 기계적인 리팩터를 적용합니다.
isolation: worktree
---

요청된 리팩터를 영향을 받는 모든 파일에 적용한 뒤,
테스트를 실행하고 결과를 보고하세요.
```

> **중요**: `isolation: worktree`는 **정의 파일**에 설정해야 합니다. Agent 도구를 호출할 때 동적으로 추가할 수 없습니다. `.claude/agents/<name>.md`에 미리 작성하거나 SDK의 `AgentDefinition` 객체에 포함해야 합니다.

### 워크트리 라이프사이클

워크트리가 생성되고 사라지는 전체 과정입니다.

**생성 시나리오:**

| 시나리오 | 생성 주체 |
|---|---|
| `claude --worktree <name>` | 사용자 명시 |
| Agent View 백그라운드 세션(파일 편집 시) | Claude Code 자동 |
| 데스크톱 앱 새 세션 | Claude Code 자동 |
| `isolation: worktree` 서브에이전트 호출당 | Claude Code 자동 |
| 세션 중 `EnterWorktree` 도구 사용 | Claude가 생성 |
| `git worktree add` 직접 실행 | 사용자 수동 |

**사용 중:**
Claude Code는 에이전트가 실행되는 동안 `git worktree lock`을 걸어 다른 프로세스가 동시에 정리하지 못하도록 보호합니다. 에이전트가 완료되면 락이 해제됩니다.

**정리 — 대화형 세션:**
- 변경 없음 + 이름 없는 세션: 자동 제거
- 변경 없음 + 이름 있는 세션: Claude가 먼저 확인
- 변경 있음: Claude가 유지 또는 제거를 확인. 제거 선택 시 디렉토리와 브랜치를 모두 삭제(작업도 함께 삭제됨)

**정리 — 비대화형/서브에이전트:**
- 변경 없는 워크트리: 서브에이전트 완료 즉시 자동 제거
- 변경 있는 워크트리: 주기적 정리(`cleanupPeriodDays`, 기본 30일) 때까지 유지
- `--worktree` 플래그로 만든 워크트리: 주기적 자동 정리 대상에서 **영구 제외**

### EnterWorktree · ExitWorktree 도구

세션 중 Claude가 직접 워크트리에 진입하거나 나올 수 있습니다.

**EnterWorktree**
- 새 격리 워크트리를 생성하고 진입하거나, 경로로 기존 워크트리에 진입합니다
- `.claude/worktrees/` 하위 경로의 신규 생성: 권한 프롬프트 없음
- 외부 경로: 항상 승인 프롬프트(CWD·쓰기 접근·프로젝트 설정이 이동하기 때문)
- 이미 워크트리 안에 있을 때: `path` 형식만 가능하며 `.claude/worktrees/` 하위여야 함

**ExitWorktree**
- 워크트리 세션을 종료하고 원래 디렉토리로 복귀합니다
- 사용자 권한 불필요
- `isolation: worktree` 서브에이전트에서는 사용할 수 없습니다
- 워크트리 간 직접 전환은 불가합니다. 종료 후 `EnterWorktree`를 다시 호출해야 합니다


## 병렬 작업과 충돌 원천 차단

### 3가지 강제 검사

워크트리 격리 세션(`--worktree`, `EnterWorktree`, `isolation: worktree`, 재개 워크트리 세션)에서는 메인 체크아웃을 건드리지 못하게 세 가지를 자동으로 차단합니다.

**a. 파일 편집 검사**

`Edit`, `Write`, `NotebookEdit` 도구가 메인 체크아웃 경로를 대상으로 하면 차단합니다.

**b. 명령어 작업 디렉토리 검사**

`Bash`, `PowerShell`, `Monitor` 명령의 CWD가 결국 메인 체크아웃을 가리키면 차단합니다.

**c. git 리디렉션 검사** (Bash·Monitor 전용)

메인 체크아웃으로 git을 리디렉션하는 명령을 차단합니다. `git -C <main-path>`, `--git-dir`, `GIT_DIR`/`GIT_WORK_TREE` 환경변수, 메인 체크아웃으로 `cd`한 뒤 git을 실행하는 경우가 모두 대상입니다.

> **서브에이전트에도 같은 규칙이 적용됩니다.** 격리 세션이 생성한 서브에이전트에 `isolation: worktree`가 없어도 부모 세션의 격리 규칙을 그대로 물려받습니다.

### 자동 병합은 없습니다

> ⚠️ **중요**: Claude Code는 워크트리 브랜치를 `main`에 자동으로 병합하지 않습니다. 결과를 어떻게 처리할지는 개발자가 결정합니다.

| 유형 | 실제 동작 |
|---|---|
| `isolation: worktree` 서브에이전트 | 최종 메시지만 부모에게 반환. 파일 변경은 워크트리 브랜치에 남음. 개발자가 검토·PR·병합을 결정 |
| Agent View 백그라운드 세션 | 완료 시 자동 커밋 및 리모트 푸시(가능한 경우). 드래프트 PR 생성 가능. `main` 직접 푸시·강제 푸시·자동 병합은 절대 없음 |
| `/batch` 스킬 | 하나의 큰 변경을 5~30개 워크트리 격리 서브에이전트로 분할. 각 서브에이전트가 자체 PR을 생성 |

병렬로 돌아가는 에이전트들이 각자 워크트리 브랜치에 작업을 쌓으면, 개발자가 결과를 검토하고 PR로 순서대로 병합하거나 취사선택합니다. 자동화가 아니라 개발자의 검토를 전제로 한 분업 구조입니다.

### 워크트리가 메인 체크아웃과 공유하는 것

격리되어 있다고 모든 것이 분리되지는 않습니다. 다음 세 가지는 워크트리와 메인 체크아웃이 함께 씁니다.

1. **`.git` 디렉토리**: 워크트리에서 실행하는 git 명령이 공유 `.git`에 씁니다. 이 쓰기는 샌드박싱이 허용합니다.
2. **프로젝트 범위 플러그인**: 메인 체크아웃에 설치된 플러그인이 워크트리에서도 로드됩니다(v2.1.200+).
3. **권한 승인**: 워크트리 세션에서 "다시 묻지 마세요"를 선택하면 메인 체크아웃의 `.claude/settings.local.json`에 저장되어 전체에 적용됩니다(v2.1.211+).

### 비용과 성능 고려사항

병렬 에이전트는 속도를 높이는 대신 비용을 그만큼 씁니다. 공식 문서 기준은 이렇습니다.

> "10개 에이전트 병렬 실행 ≈ 10배 빠른 쿼터 소비"

에이전트 팀의 경우:
> "팀원이 plan 모드로 실행될 때 표준 세션보다 약 7배 토큰 소비"

백그라운드 유휴 상태에서는:
> "백그라운드 프로세스는 세션당 일반적으로 $0.04 미만 소비"

워크트리 격리 자체는 비용을 크게 늘리지 않습니다. 비용의 주 요인은 에이전트 수와 각 에이전트가 처리하는 작업량입니다.

> 🔀 **네이티브 vs 팀 (연결)**: 이 절의 워크트리 격리(`isolation: worktree`)는 한 세션 내에서 서브에이전트 간 충돌을 막는 방식입니다. 5-3(서버 모드 worktree 격리)에서 다루는 팀 기반 격리, 9-4(충돌 방지)의 Redis 기반 상태 공유와 대비됩니다. 단발성 병렬 작업은 이 절의 네이티브 방식이, 오래 이어지는 역할 분리와 팀 협업은 팀 기반 방식이 적합합니다.
