## 03-6. CLAUDE.md 기초

`claude`를 실행할 때마다 "항상 한국어로 응답해줘", "테스트는 pytest를 써줘", "커밋 메시지는 한국어로"처럼 반복해서 입력하는 것은 번거롭습니다. **CLAUDE.md**는 이런 지침을 파일에 한 번 써 두면 세션을 열 때마다 자동으로 Claude에게 전달되는 **프로젝트 지침 파일**입니다. 이 절에서는 CLAUDE.md가 무엇인지, 어디에 두어야 하는지, 그리고 바로 쓸 수 있는 최소한의 내용을 익힙니다.

> **이 페이지 범위**: CLAUDE.md 개념 · 파일 계층 4종 · `/init`으로 시작하기 · 간단한 작성 요령. 팀 CLAUDE.md를 역할 정의·에이전트 위임에 활용하는 심화 내용은 04-4에서 다룹니다.

> 🔀 **심화는 04-4(연결)**: CLAUDE.md를 팀 워크플로우·멀티에이전트 위임에 연결하는 방법은 04-4(CLAUDE.md로 팀 역할 정의하기)에서 다룹니다. 여기서는 "개인 프로젝트에서 기초 활용"에 집중합니다.

<hr>

## CLAUDE.md란 무엇인가

CLAUDE.md는 마크다운으로 작성하는 텍스트 파일입니다. Claude Code는 세션을 시작할 때 이 파일을 읽어 컨텍스트 창에 자동으로 로드합니다. 여러분이 매 세션 첫 줄에 써야 했던 지침이 이제 파일 안에 들어있는 것입니다.

```
세션마다 반복 입력:                  CLAUDE.md에 한 번 작성:
> 항상 한국어로 답해줘            →  ## 언어
> 테스트는 pytest만 써줘         →  - 항상 한국어로 응답
> 커밋 메시지는 영어로            →  - 테스트: pytest만 사용
> 들여쓰기는 4스페이스            →  - 커밋 메시지: 영어
                                   - 들여쓰기: 4스페이스
```

Claude는 CLAUDE.md를 **지시로 받아들입니다**. 파일에 "들여쓰기는 2스페이스"라고 쓰면 코드를 수정할 때마다 그 규칙을 따릅니다.

> 💡 CLAUDE.md는 Claude **Code**가 읽는 파일입니다. Claude.ai 웹 인터페이스나 다른 Claude 제품에는 적용되지 않습니다.

<hr>

## 파일 계층 — 어디에 두느냐에 따라 적용 범위가 달라집니다

CLAUDE.md는 위치에 따라 적용 범위가 달라집니다. 네 계층이 있습니다.

| 계층 | 위치 | 적용 범위 | Git 관리 |
|---|---|---|---|
| **관리형 정책** | Linux/WSL: `/etc/claude-code/CLAUDE.md`<br>macOS: `/Library/Application Support/ClaudeCode/CLAUDE.md` | 이 머신의 모든 사용자 | 조직 배포 |
| **사용자** | `~/.claude/CLAUDE.md` | 내 모든 프로젝트 | git 미관리 |
| **프로젝트** | `./CLAUDE.md` 또는 `./.claude/CLAUDE.md` | 이 프로젝트 전체 (팀 공유) | ✅ 커밋 가능 |
| **로컬** | `./CLAUDE.local.md` | 이 프로젝트, 개인용 | `.gitignore`에 추가 |

**가장 자주 쓰는 두 계층**:

- **`~/.claude/CLAUDE.md`** — 언어 설정, 선호 스타일처럼 모든 프로젝트에 공통으로 적용할 개인 지침을 둡니다.
- **`./CLAUDE.md`** — 이 프로젝트만의 규칙(코딩 컨벤션, 테스트 프레임워크, 아키텍처 원칙)을 팀과 함께 git으로 관리합니다.

여러 계층의 CLAUDE.md가 있으면 Claude Code는 **루트에서 현재 디렉터리 방향으로** 순서대로 읽어 모두 합칩니다. 더 구체적인(하위 디렉터리의) 파일이 나중에 읽히므로 우선순위가 높습니다.

> ⚠️ **흔한 실수**: 프로젝트 CLAUDE.md에 API 키, 비밀번호 같은 민감한 정보를 쓰면 git에 올라갈 수 있습니다. 개인 정보는 `./CLAUDE.local.md`(`.gitignore`에 추가)에 쓰세요.

## `/init`으로 CLAUDE.md 시작하기

프로젝트 디렉터리에서 `/init` 명령을 실행하면 Claude Code가 현재 프로젝트를 분석해 CLAUDE.md 초안을 자동으로 생성해 줍니다.

```
> /init
```

Claude가 코드베이스를 살펴본 뒤 프로젝트에 맞는 CLAUDE.md를 만들어 줍니다.

```
CLAUDE.md를 생성했습니다:

## 프로젝트 개요
Python 기반 웹 API 프로젝트

## 개발 환경
- Python 3.11
- FastAPI
- PostgreSQL

## 코딩 컨벤션
- 들여쓰기: 4스페이스
- 타입 힌트 사용
...
```

생성된 파일을 열어 불필요한 내용을 지우고 빠진 지침을 추가하면 됩니다. 처음부터 빈 파일에 작성하는 것보다 훨씬 빠른 시작점입니다.

## 간단한 CLAUDE.md 작성 요령

CLAUDE.md는 마크다운 헤더와 불릿으로 작성합니다. 지침은 구체적일수록 효과적입니다.

**좋은 예 vs. 나쁜 예**:

| ❌ 모호한 표현 | ✅ 구체적인 표현 |
|---|---|
| "코드를 올바르게 포맷해" | "들여쓰기: 2스페이스, 문자열은 작은따옴표" |
| "테스트를 잘 써줘" | "테스트 프레임워크: pytest, 파일명: `test_*.py`" |
| "커밋 메시지 신경 써줘" | "커밋 메시지: `type(scope): 설명` 형식, 영어로" |

**최소한의 CLAUDE.md 예시**:

```markdown
## 언어
- 응답은 항상 한국어로

## 코딩 규칙
- 들여쓰기: 4스페이스
- 타입 힌트 사용 필수
- 함수 이름: snake_case

## 테스트
- 프레임워크: pytest
- 커버리지 80% 이상 유지

## Git
- 커밋 메시지: 영어, `feat:` / `fix:` / `docs:` 접두어
```

**파일 크기**: 한 파일당 **200줄 미만**을 권장합니다. 초과하면 세션 시작 시 경고가 표시됩니다. 내용이 많다면 `@import` 문법으로 여러 파일로 나눌 수 있습니다.

```markdown
# CLAUDE.md
@docs/coding-conventions.md
@docs/test-guide.md
```

`@`로 시작하는 줄은 해당 파일을 통째로 불러옵니다. 백틱으로 감싸면(`@README`) 임포트가 아니라 파일 이름 참조로 처리됩니다.

> ⚠️ **흔한 실수**: `@`와 백틱을 혼동하는 경우가 있습니다. `` `@README` ``(백틱 안)는 파일을 **임포트하지 않습니다**. 실제로 파일 내용을 불러오려면 백틱 없이 `@README.md`로 써야 합니다.

## CLAUDE.md 편집·점검

**세션 중 편집**: `/memory` 명령을 쓰면 CLAUDE.md 파일을 편집하거나 자동 메모리 항목을 관리할 수 있습니다.

```
> /memory
```

**지침 점검**: 시간이 지나면 CLAUDE.md에 오래된 지침이나 서로 충돌하는 내용이 생길 수 있습니다. `/doctor prompt-audit`으로 현재 지침을 감사할 수 있습니다.

```
> /doctor prompt-audit
```

Claude Code가 CLAUDE.md 전체를 검토해 오래된 지시·충돌·중복을 알려줍니다.

## `.claude/rules/` — 경로별 규칙 분리 (선택)

프로젝트가 커지면 모든 규칙을 하나의 CLAUDE.md에 넣는 대신, **특정 경로에서만 적용되는 규칙**을 분리할 수 있습니다.

```yaml
# .claude/rules/api-design.md
---
paths:
  - "src/api/**/*.ts"
---
## API 설계 원칙
- REST 엔드포인트는 복수 명사: `/users`, `/orders`
- 응답은 반드시 `{ data, error, meta }` 구조 유지
```

`paths` 필드가 있으면 Claude가 해당 경로의 파일을 접근할 때만 이 규칙이 로드됩니다. `paths` 없이 `.claude/rules/`에 두면 모든 세션에 항상 로드됩니다. 컨텍스트 창을 절약하면서 규칙을 정교하게 관리할 수 있습니다.

> 🔀 **심화는 04-4(연결)**: `.claude/rules/`를 에이전트별로 분리하고, CLAUDE.md로 멀티에이전트 팀의 역할을 정의하는 방법은 04-4에서 다룹니다.

## 정리

CLAUDE.md는 세 줄로 요약됩니다.

```
~/.claude/CLAUDE.md   → 개인 전체 지침 (언어·스타일)
./CLAUDE.md           → 프로젝트 공유 지침 (컨벤션·테스트)
./CLAUDE.local.md     → 개인 전용 지침 (민감 정보·임시 규칙)
```

오늘 당장 시작하려면 `/init`으로 초안을 만들고, 팀과 맞지 않는 부분을 수정한 뒤 git에 커밋하세요.

다음 03-7에서는 **컨텍스트 관리 기초**를 다룹니다. 토큰이 무엇인지, 컨텍스트 창이 꽉 찼을 때 어떻게 대응하는지를 익히고, 단일 세션의 한계를 느끼면서 자연스럽게 04장(멀티에이전트)으로 이어지는 이유를 이해하게 됩니다.
