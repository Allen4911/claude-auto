## 03-7. 컨텍스트 관리 기초

Claude Code를 쓰다 보면 어느 순간 응답이 느려지거나, 앞에서 했던 말을 Claude가 잊는 것처럼 느껴지는 때가 생깁니다. 이런 현상의 원인은 대부분 **컨텍스트 창**에 있습니다. 이 절에서는 컨텍스트 창이 무엇인지, 토큰이 어떻게 쌓이는지, 그리고 `/clear`와 `/compact`로 컨텍스트를 실전에서 관리하는 방법을 익힙니다. 절 말미에는 단일 세션의 한계를 통해 **왜 멀티에이전트로 넘어가는지**를 자연스럽게 연결합니다.

> **이 페이지 범위**: 컨텍스트 창 개념 · 토큰 감각 · `/context`로 사용량 확인 · `/compact`와 `/clear` 실전 · 자동 컴팩트 · 단일 세션 한계. 컨텍스트 관리 심화(분할 전략·토큰 최적화)는 10-3에서 다룹니다.

> 🔀 **심화는 10-3(연결)**: 대규모 코드베이스에서 컨텍스트를 전략적으로 분할하고 토큰을 최적화하는 방법은 10-3(컨텍스트 관리 심화)에서 다룹니다. 여기서는 일상 세션에서 즉시 쓸 수 있는 기초에 집중합니다.

<hr>

## 컨텍스트 창이란

Claude는 대화할 때 **지금까지 나눈 모든 내용**을 한 번에 올려다보며 답합니다. 이 "올려다보는 창"이 **컨텍스트 창(context window)**입니다. 크기에는 한계가 있습니다.

```
┌─────────────────────────────────────────────┐
│  컨텍스트 창                                 │
│                                             │
│  [CLAUDE.md 내용]                           │
│  [대화 1턴: 질문 + 응답]                     │
│  [대화 2턴: 질문 + 응답]                     │
│  ...                                        │
│  [대화 N턴: 질문 + 응답]  ← 지금 여기        │
│                                             │
│  ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ 42% 사용   │
└─────────────────────────────────────────────┘
```

창에 올라온 내용이 많을수록 Claude는 더 많은 맥락을 참고하지만, 창이 꽉 찰수록 처리 속도가 느려지고 비용이 늘어납니다. 창이 한계를 넘으면 Claude Code가 자동으로 대화를 요약하거나 경고를 표시합니다.

<hr>

## 토큰 — 컨텍스트의 단위

컨텍스트 창의 크기는 **토큰(token)** 단위로 측정합니다. 토큰은 단어와 비슷하지만 완전히 같지는 않습니다.

- 한국어 1글자 ≈ 1~2토큰
- 영어 단어 1개 ≈ 1토큰
- 코드 한 줄 ≈ 10~30토큰 (내용에 따라 다름)

**실제 느낌으로 환산하면**:

| 내용 | 대략적인 토큰 수 |
|---|---|
| 짧은 질문 한 줄 | 10~30토큰 |
| 코드 파일 100줄 | 800~1,500토큰 |
| 대화 10턴 (질문·응답 포함) | 2,000~10,000토큰 |
| 200줄 CLAUDE.md | 3,000~5,000토큰 |

모델마다 컨텍스트 창 크기가 다릅니다. Sonnet 5.5 · Fable 5.1 등 최신 모델은 **100만 토큰(1M)** 이상을 지원하고, 이전 모델은 200K 수준입니다. [검증필요: 모델별 최신 컨텍스트 창 크기 — 버전 업에 따라 변경될 수 있음]

> 💡 토큰 수를 정확히 계산할 필요는 없습니다. "파일을 많이 읽히거나 대화가 길어질수록 컨텍스트가 쌓인다"는 감각만 가지고 있으면 됩니다. 실제 사용량은 `/context`로 확인합니다.

<hr>

## `/context` — 지금 얼마나 쌓였나

현재 세션의 컨텍스트 사용량을 시각적으로 확인합니다.

```
> /context
```

컬러 그리드로 사용량이 표시되고, 최적화 제안이나 용량 경고가 함께 나옵니다.

```
컨텍스트 사용량

█████████████░░░░░░░░░░░░░░░░░░░░  42,300 / 200,000 토큰 (21%)

제안: 대화가 길어지고 있습니다. /compact로 요약하거나
      /clear로 새 대화를 시작할 수 있습니다.
```

상세 정보를 보려면 `all`을 붙입니다.

```
> /context all
```

**언제 확인하나**: 응답이 느려지거나 Claude가 앞서 한 말을 잊는 것 같을 때 먼저 `/context`로 사용량을 확인하세요. 70% 이상이면 `/compact`를 고려할 시점입니다.

<hr>

## `/compact` — 맥락은 살리고 공간은 확보

`/compact`는 긴 대화를 **핵심 내용으로 요약**해 컨텍스트 공간을 확보합니다. 대화를 버리지 않고 압축하므로 같은 작업을 계속 이어가면서 토큰을 줄일 수 있습니다.

```
> /compact
```

선택적으로 **무엇을 중심으로 요약할지** 지시를 함께 전달할 수 있습니다.

```
> /compact 인증 모듈 리팩터링 내용 중심으로 요약해줘
```

압축 전후 비교:

```
압축 전: 42,300 토큰 (21%)
압축 후:  8,200 토큰  (4%)

요약 완료. 주요 결정 사항과 작업 맥락이 유지됩니다.
```

**`/compact` 후 보존되는 것과 그렇지 않은 것**:

| 항목 | `/compact` 후 |
|---|---|
| 프로젝트 루트 `CLAUDE.md` | ✅ 자동 재로드 |
| 하위 디렉터리 `CLAUDE.md` | ✅ 해당 파일 접근 시 재로드 |
| 대화 중 직접 전달한 지시 | ❌ 요약에서 빠질 수 있음 |
| 파일 변경 이력(git) | ✅ 파일 시스템에 남아 있음 |

> ⚠️ **흔한 실수**: 대화 중 "이번 세션에서만 적용" 방식으로 전달한 지시(예: "지금부터 응답을 짧게 해줘")는 `/compact` 후 사라질 수 있습니다. 항상 적용하고 싶은 지침은 `CLAUDE.md`에 기록해 두세요.

<hr>

## `/clear` — 새로 시작

`/clear`는 컨텍스트 창을 완전히 비우고 새 대화를 시작합니다. 이전 대화 내용을 Claude가 더 이상 참조하지 않습니다.

```
> /clear
✓ 새 대화를 시작합니다.

>
```

나중에 이 세션으로 돌아가고 싶다면 이름을 붙여 저장할 수 있습니다.

```
> /clear 인증리팩터링-1차
```

이름을 붙이면 `/resume` 목록에 "인증리팩터링-1차"로 저장되어 나중에 불러올 수 있습니다.

**`/compact` vs. `/clear` 선택 기준**:

| 상황 | 권장 명령 |
|---|---|
| 같은 작업 계속 — 맥락 유지하며 토큰만 줄이기 | `/compact` |
| 완전히 다른 주제로 전환 | `/clear` |
| 오늘 작업 마무리 후 깔끔하게 정리 | `/clear [이름]` |
| 컨텍스트가 포화 직전, 작업 계속해야 할 때 | `/compact` 후 이어가기 |

<hr>

## 자동 컴팩트 — 임계값 설정

매번 수동으로 `/compact`를 실행하지 않아도 됩니다. 컨텍스트가 일정 수준에 도달하면 Claude Code가 자동으로 요약을 실행하도록 임계값을 설정할 수 있습니다.

**세션 중 설정**:

```
> /autocompact 500k     # 500K 토큰 도달 시 자동 요약
> /autocompact auto     # Claude Code가 자동 판단
```

**시작 시 플래그로**:

```bash
claude --autocompact 500k
```

기본 임계값은 모델에 따라 다릅니다. Sonnet 5.5·Fable 5.1 등 1M 컨텍스트 모델은 약 967K 토큰, 구형(200K 컨텍스트) 모델은 200K를 기본값으로 씁니다.

> 💡 자동 컴팩트가 발동할 때 Claude Code는 현재 진행 중인 작업을 마친 뒤 요약합니다. 요약 중에는 잠깐 대기 시간이 생길 수 있습니다.

<hr>

## 컨텍스트 관리 실전 팁

1. **선제적으로 `/compact`** — 꽉 찬 뒤보다 여유 있을 때 요약 품질이 좋습니다. `/context`로 70% 이상이면 미리 실행합니다.
2. **자주 쓰는 지침은 `CLAUDE.md`에** — `/compact` 후에도 재로드되므로 사라지지 않습니다.
3. **새 주제 시작 = `/clear`** — 이전 맥락이 새 작업을 방해하지 않습니다. 이름을 붙이면(`/clear 작업명`) 나중에 `/resume`으로 돌아올 수 있습니다.

<hr>

## 단일 세션의 한계 — 그리고 멀티에이전트로

컨텍스트 관리를 잘 해도 단일 세션에는 구조적 한계가 있습니다.

**첫 번째 한계 — 크기**: 아무리 큰 컨텍스트 창도 대형 코드베이스 전체를 한 번에 담을 수는 없습니다. "전체 코드를 다 읽고 최적화해줘"는 수백만 줄이라면 현실적으로 불가능합니다.

**두 번째 한계 — 속도**: 컨텍스트가 클수록 응답이 느립니다. 독립적인 작업 세 개를 순서대로 처리하면 세 배의 시간이 걸립니다.

**세 번째 한계 — 집중**: 한 세션에서 파일 파싱, API 수정, 문서 작성을 동시에 맡기면 Claude의 주의가 분산됩니다. 각 작업에 전용 컨텍스트를 주는 것이 품질도 높습니다.

```
[단일 세션]
작업A → 작업B → 작업C    (순서대로, 느림, 컨텍스트 혼잡)

[멀티에이전트]
작업A ─┐
작업B ─┼─ 동시 실행    (병렬, 빠름, 각자 깨끗한 컨텍스트)
작업C ─┘
```

이 한계가 **멀티에이전트**가 필요한 이유입니다. Claude Code는 하나의 Claude가 여러 서브에이전트를 띄워 작업을 나눠 맡기는 방식을 기본으로 지원합니다. 각 서브에이전트는 완전히 새로운 빈 컨텍스트에서 시작하므로, 이전 대화의 잡음 없이 자신의 작업에만 집중합니다.

단일 세션에서 컨텍스트 관리를 배운 이유가 여기에 있습니다 — 단일 세션의 리듬을 몸에 익혀야 멀티에이전트로 작업을 분배하는 판단도 자연스럽게 생깁니다.

> 🔀 **04장으로(연결)**: 04장부터는 Claude Code 고유의 **네이티브 멀티에이전트** — 한 Claude가 여러 서브에이전트를 호출해 작업을 분산하는 방식 — 를 다룹니다. 지금까지 익힌 기초(REPL·편집·슬래시 명령·CLI·Plan Mode·CLAUDE.md·컨텍스트)가 모두 그 위에서 작동하는 토대입니다.

<hr>

이제 Claude Code 기본기를 갖췄습니다 — REPL·편집·슬래시 명령·CLI·Plan Mode·CLAUDE.md·컨텍스트까지. 04장에서 본격적인 멀티에이전트의 세계로 들어갑니다.
