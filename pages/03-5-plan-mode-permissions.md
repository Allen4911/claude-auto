## 03-5. Plan Mode와 권한 시스템

Claude Code는 여러분의 파일과 터미널에 직접 접근할 수 있습니다. 강력한 만큼 "Claude가 예상 밖의 파일을 건드리면 어떡하지?"라는 걱정도 생깁니다. 이 절에서 익힐 **Plan Mode와 권한 시스템**은 그 걱정을 해소하는 안전망입니다 — Claude가 먼저 계획을 세우게 하거나, 어떤 도구를 어느 수준까지 허용할지 직접 제어하는 방법을 익혀서 **신뢰하면서도 통제할 수 있는** 위임 방식을 만듭니다.

> **이 페이지 범위**: Plan Mode 개념과 진입 방법 · 권한 모드 여섯 가지 · 도구별 승인 기준 · 세션 중 모드 전환(Shift+Tab) · 기본값 설정(`settings.json`). Plan Mode를 팀 전체에 적용하는 방법은 03-6(CLAUDE.md 기초)와 함께 다룹니다.

<hr>

## Plan Mode란 — "먼저 계획, 그 다음 실행"

일반 모드에서 Claude는 파일 편집이나 명령 실행을 요청받으면 곧바로 실행하고 승인을 구합니다. **Plan Mode**에서는 순서가 바뀝니다.

```
[일반 모드]
지시 입력 → Claude가 편집/명령 실행 → diff 확인 → 승인

[Plan Mode]
지시 입력 → Claude가 계획만 제시 → 계획 확인·수정 → 승인 후 실행
```

Plan Mode가 켜진 상태에서 Claude는 파일을 건드리거나 터미널 명령을 실행하는 대신, 무엇을 어떻게 할 것인지 **계획(plan)만** 먼저 내놓습니다. 여러분이 계획을 확인하고 "진행해"라고 승인해야 비로소 실행합니다.

```
> 인증 모듈 전체를 JWT 방식으로 리팩터링해줘

[계획 모드]
다음 단계로 진행하기 전에 계획을 먼저 정리하겠습니다:

1. src/auth/session.py — 세션 기반 인증 코드 제거, JWT 발급 함수 추가
2. src/auth/middleware.py — 쿠키 검증 → JWT 헤더 검증으로 교체
3. tests/test_auth.py — 기존 세션 테스트 제거, JWT 토큰 테스트 추가
4. requirements.txt — PyJWT 라이브러리 추가

이 계획대로 진행할까요?
```

계획이 마음에 들면 "진행해" 또는 "yes"를 입력합니다. 수정이 필요하면 그 자리에서 "3번은 건드리지 말고 1, 2만 해줘"처럼 지시를 조정한 뒤 다시 확인합니다.

> 💡 Plan Mode는 큰 리팩터링이나 여러 파일에 걸친 변경처럼 **범위를 먼저 파악해야 할 작업**에 특히 유용합니다. 작은 수정은 일반 모드로, 큰 변경은 Plan Mode로 시작하는 습관을 들이면 실수를 크게 줄일 수 있습니다.

## Plan Mode 진입 방법 세 가지

Plan Mode에 들어가는 방법은 세 가지입니다.

**① 시작 시 플래그로**:

```bash
claude --permission-mode plan
```

세션을 처음 열 때부터 Plan Mode로 시작합니다. 처음부터 큰 작업을 맡길 때 권장합니다.

**② 세션 중 슬래시 명령으로**:

```bash
> /plan
> /plan 인증 버그 수정    # 설명과 함께 바로 해당 작업으로 시작
```

세션 도중 Plan Mode로 전환합니다. 설명을 함께 입력하면 Claude가 해당 작업의 계획부터 즉시 제시합니다.

**③ 세션 중 Shift+Tab으로 사이클**:

`Shift+Tab`을 누를 때마다 권한 모드가 순서대로 전환됩니다.

```
auto → default → acceptEdits → plan → (다시 auto로)
```

현재 모드는 상태바에 표시됩니다.

```
⏸ plan mode on          # Plan Mode 활성화 상태
```

> ⚠️ **흔한 실수**: Plan Mode가 켜진 상태에서 "그냥 이 파일만 빠르게 고쳐줘"처럼 소규모 편집을 맡기면 Claude가 계획을 먼저 내놔서 느릴 수 있습니다. 작은 작업이 많을 때는 `Shift+Tab`으로 `acceptEdits` 모드로 전환하세요.

## 권한 모드 여섯 가지

Claude Code는 도구 사용 승인 방식을 **여섯 가지 모드**로 조정할 수 있습니다. 세션 중 `Shift+Tab`으로 전환하거나 시작 시 `--permission-mode` 플래그로 지정합니다.

| 모드 | 설정값 | 특징 |
|---|---|---|
| **Manual 모드** | `default` | 파일 읽기만 자동 허용, 나머지는 모두 확인 요청 |
| **Accept Edits 모드** | `acceptEdits` | 읽기 + 파일 편집 + 기본 파일시스템 명령 자동 허용 |
| **Plan 모드** | `plan` | 모든 편집 차단, 계획만 제시 → 승인 후 실행 |
| **Auto 모드** | `auto` | 분류기(classifier)가 대신 승인 판단 |
| **Bypass 모드** | `bypassPermissions` | 모든 권한 확인 우회 (컨테이너 전용 권장) |
| **Don't Ask 모드** | `dontAsk` | 비대화형 CI 실행용, 허용 툴 목록 명시 필요 |

**일반 사용자가 실제로 쓰는 모드는 넷**입니다.

**`default` (Manual)**: 가장 명시적인 모드입니다. Claude가 파일을 읽는 것은 자동으로 허용되지만, 편집·명령 실행은 매번 확인을 요청합니다. 처음 Claude Code를 쓸 때 권장합니다.

**`acceptEdits`**: 파일 편집까지 자동 허용해서 승인 단계를 줄입니다. `mkdir`, `mv`, `cp` 같은 기본 파일시스템 명령도 자동 허용됩니다. 신뢰할 수 있는 프로젝트에서 반복 편집 작업을 빠르게 처리할 때 적합합니다.

**`plan`**: 앞 섹션에서 설명한 Plan Mode입니다. 모든 편집이 차단되고 계획만 제시합니다.

**`auto`**: Claude Code 자체의 분류기(classifier)가 각 도구 호출을 요청 내용과 대조하는 배경 안전 검사를 수행해 승인 여부를 자동으로 판단합니다. `/permissions`의 "Auto mode" 탭에서 분류기 규칙을 확인하고 편집할 수 있습니다.

> ⚠️ **흔한 실수**: `bypassPermissions`는 자동화 컨테이너 환경 전용입니다. 로컬 개발 환경에서 "매번 승인이 귀찮다"는 이유로 사용하면 원하지 않는 파일 변경이나 명령 실행이 일어날 수 있습니다.

## 도구별 기본 승인 기준

Manual 모드(`default`) 기준으로 각 도구 유형이 어떻게 처리되는지 알아두면 승인 요청이 뜨는 이유를 파악할 수 있습니다.

| 도구 유형 | 예시 | 자동 허용? |
|---|---|---|
| 파일 읽기, 검색 | Read, grep, glob | ✅ 작업 디렉터리 내 자동 |
| 파일 편집·쓰기 | Edit, Write | ❌ 확인 요청 |
| 셸 명령 실행 | Bash | ❌ 확인 요청 (일부 읽기 전용 제외) |
| 웹 요청 | WebFetch, WebSearch | ❌ 확인 요청 (사전 승인 도메인 제외) |

파일 읽기가 자동 허용되는 이유는 읽기만으로는 파일이 바뀌지 않기 때문입니다. 반면 셸 명령은 어떤 명령이 실행될지 예측할 수 없으므로 매번 확인을 요청합니다.

**승인 요청 화면 예시**:

```
Bash 명령을 실행하려 합니다:

  python -m pytest tests/

실행을 허용하시겠습니까? (y/n/항상 허용)
```

`y`로 한 번 허용하거나, "항상 허용"을 선택하면 이 세션에서 같은 명령은 다시 묻지 않습니다.

## 세션 중 모드 전환 — Shift+Tab

작업 성격에 따라 세션 도중에도 모드를 바꿀 수 있습니다. `Shift+Tab`을 누를 때마다 모드가 순환합니다.

```
auto → default → acceptEdits → plan → (다시 auto)
```

**활용 패턴**:

| 상황 | 전환할 모드 |
|---|---|
| 큰 리팩터링을 시작하기 전 | `plan` — 먼저 범위 확인 |
| 반복적인 소규모 편집 | `acceptEdits` — 승인 단계 생략 |
| 새로운 영역 탐색 | `default` — 명시적 확인 |
| 평소 일반 작업 | `auto` — Claude Code 자동 판단 |

현재 모드는 상태바에서 항상 확인할 수 있습니다.

<hr>

## 기본 모드 영구 설정 — `settings.json`

매번 플래그를 입력하거나 `Shift+Tab`으로 전환하는 대신 기본 모드를 파일로 고정할 수 있습니다.

**프로젝트 전용 설정** (`.claude/settings.json`):

```json
{
  "permissions": {
    "defaultMode": "default"
  }
}
```

**개인 전체 설정** (`~/.claude/settings.json`):

```json
{
  "permissions": {
    "defaultMode": "auto"
  }
}
```

설정값으로 `default`, `acceptEdits`, `plan`, `auto` 중 하나를 씁니다.

> 🔀 **설정 파일 계층(연결)**: `.claude/settings.json`(프로젝트 공유)과 `.claude/settings.local.json`(개인 전용), `~/.claude/settings.json`(전역) 파일의 우선순위 관계는 03-6(CLAUDE.md 기초)에서 설정 계층 전체를 다루며 함께 설명합니다.

## 정리

권한 시스템의 핵심은 단순합니다 — **Claude가 무엇을 할 수 있는지 여러분이 결정**합니다.

```
Plan Mode      : 실행 전에 계획 확인 → 큰 변경에 적합
default 모드   : 매 도구 호출마다 확인 → 신중한 탐색에 적합
acceptEdits    : 편집 자동 허용 → 반복 작업에 적합
auto 모드      : Claude Code 자동 판단 → 일반 작업 기본값
```

모드는 `Shift+Tab`으로 언제든 바꿀 수 있고, `settings.json`으로 기본값을 고정할 수 있습니다.

다음 03-6에서는 **CLAUDE.md**를 다룹니다. 프로젝트에 CLAUDE.md 파일을 두면 "항상 한국어로 응답해", "테스트는 pytest 사용" 같은 지침이 세션을 열 때마다 자동으로 적용됩니다. 권한 설정을 프로젝트 단위로 팀과 공유하는 방법도 그 절에서 함께 설명합니다.
