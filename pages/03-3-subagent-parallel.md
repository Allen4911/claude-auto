# 03-3. Subagent 작업 분담과 병렬 실행

서브에이전트를 하나씩 순서대로 쓰는 건 그냥 Claude를 여러 번 호출하는 것과 큰 차이가 없습니다. 네이티브 멀티에이전트의 진가는 여러 에이전트가 동시에 독립적으로 달리는 병렬 실행에서 나옵니다. 이 절에서는 작업을 나누는 방법과 병렬 실행의 규칙, 결과를 취합하는 패턴을 다룹니다.

<hr>

## 작업 분담 전략

병렬 실행을 하려면 먼저 작업을 나눌 수 있어야 합니다. 작업을 분담하기 전에 스스로 다음 질문을 던져 봅니다.

**작업 A가 작업 B의 결과에 의존하는가?**

- **의존함**: 순차 실행. A가 끝난 뒤 B를 시작합니다.
- **의존 안 함**: 병렬 실행 가능.

### 병렬화하기 좋은 작업 유형

| 유형 | 예시 |
|---|---|
| 독립 파일 분석 | 파일 A 린트, 파일 B 린트, 파일 C 린트 동시 실행 |
| 동일 작업 × 다른 대상 | 10개 모듈 각각 유닛 테스트 작성 |
| 리서치 병렬화 | 공식 문서 탐색 + 코드베이스 탐색 동시 실행 |
| 독립 기능 구현 | UI 컴포넌트 A, API 엔드포인트 B 동시 구현 |

### 병렬화를 피해야 하는 작업 유형

| 유형 | 이유 |
|---|---|
| 같은 파일을 수정하는 작업들 | 두 에이전트가 동일 파일을 편집하면 충돌 |
| 이전 단계 결과가 입력인 작업 | 의존성 때문에 먼저 끝난 것을 기다려야 함 |
| 전역 상태를 변경하는 작업 | 실행 순서가 결과에 영향을 줌 |

> ⚠️ **충돌 주의**: 두 서브에이전트가 같은 파일을 동시에 편집하면 나중에 완료된 쪽이 앞선 쪽의 변경을 덮어씁니다. 병렬로 파일을 수정할 때는 작업 범위(파일·함수)가 겹치지 않는지 먼저 확인하세요.

## 병렬 실행과 동시성

### 병렬 실행 방법

Claude가 여러 Agent 도구를 한 번에 호출하면 병렬 실행이 시작됩니다. 사용자가 별도로 지시하지 않아도 Claude가 독립 작업임을 판단하면 자동으로 병렬 호출을 선택합니다.

```
[부모 Claude]
  ├─ Agent 도구: "파일 A 분석해줘" ─▶ [서브에이전트 1] 실행 중
  ├─ Agent 도구: "파일 B 분석해줘" ─▶ [서브에이전트 2] 실행 중
  └─ Agent 도구: "파일 C 분석해줘" ─▶ [서브에이전트 3] 실행 중
                                                 ↓ 모두 완료
  ◀─────────────── 결과 취합 ──────────────────────
```

### 동시성 제한

병렬 실행에는 시스템 제한이 있습니다.

| 제한 항목 | 기본값 | 변경 방법 |
|---|---|---|
| 동시 서브에이전트 수 | **20개** | `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 환경변수 |
| 중첩 깊이 | **3레이어** | `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 환경변수 |

**동시 20개 제한**: 세션당 동시에 실행 중인 서브에이전트가 20개를 초과하면 `Concurrent subagent limit reached` 오류가 발생합니다. 20개 이상을 한꺼번에 띄우려면 환경변수로 한도를 늘리거나 작업을 묶음으로 나눠서 순차적으로 처리합니다.

**중첩 3레이어 제한**: 서브에이전트가 또 다른 서브에이전트를 띄우고 그 서브에이전트가 다시 다음 서브에이전트를 띄울 수 있습니다. 다만 기본값은 메인 세션 아래 3레이어까지입니다. 한도에 도달하면 해당 서브에이전트에서 Agent 도구가 제거됩니다.

```
메인 세션 (레이어 0)
  └─ 서브에이전트 A (레이어 1)
        └─ 서브에이전트 B (레이어 2)
              └─ 서브에이전트 C (레이어 3) ← 여기서 Agent 도구 없음
```

> 💡 **비용 인식**: 병렬 실행은 속도를 높이는 대신 쿼터를 더 씁니다. N개 에이전트를 동시에 실행하면 쿼터 소비도 약 N배가 됩니다. 병렬화로 얻는 시간 절약과 비용 증가를 함께 고려하세요.

### 포그라운드 vs 백그라운드

서브에이전트 실행 모드는 두 가지입니다.

| 모드 | 동작 | 언제 씀 |
|---|---|---|
| **백그라운드** (기본값) | 부모가 계속 진행, 완료 알림이 이후 턴에 도착 | 결과를 바로 쓰지 않아도 될 때 |
| **포그라운드** | 서브에이전트 완료까지 부모 블로킹 | 다음 단계가 이 결과에 의존할 때 |

포그라운드 실행을 강제하려면 정의 파일 프론트매터에 `background: false`를 추가하거나 Agent 도구 호출 파라미터에 `run_in_background: false`를 지정합니다.

## 결과 취합·병합

서브에이전트의 결과는 **마지막 텍스트 출력**만 부모에게 돌아옵니다. 중간 과정·도구 호출 내역은 부모가 볼 수 없습니다.

### 결과 형식을 통일하라

여러 서브에이전트 결과를 합칠 때 형식이 제각각이면 취합하기 어렵습니다. 그래서 위임 프롬프트에 출력 형식을 명시합니다.

**나쁜 위임 프롬프트:**
```
파일 A를 분석해서 이슈를 찾아줘.
```

**좋은 위임 프롬프트:**
```
파일 A를 분석해서 이슈를 찾아줘.
결과는 다음 형식으로만 출력해:
- [파일명:줄번호] 이슈 설명 (심각도: CRITICAL/MAJOR/MINOR)
형식 외 다른 텍스트는 출력하지 마.
```

형식을 통일하면 부모 Claude가 결과를 파싱해서 취합하거나 다음 에이전트에 전달하기 쉬워집니다.

### 취합 패턴

**패턴 1: 단순 합산**

독립 분석 결과를 이어 붙이는 가장 단순한 방법입니다. 파일별 분석 결과를 모아서 통합 보고서를 만들 때 씁니다.

```
서브에이전트 1 결과 + 서브에이전트 2 결과 + 서브에이전트 3 결과
          ↓
      부모가 중복 제거 후 최종 정리
```

**패턴 2: 투표(Voting)**

같은 주제를 여러 서브에이전트가 독립적으로 분석하고 보수적 판단 원칙을 적용합니다. 단독 분석보다 신뢰성이 높습니다.

```
[서브에이전트 1]: "이 코드는 안전함"
[서브에이전트 2]: "이 코드는 안전함"
[서브에이전트 3]: "이 코드에 XSS 취약점 있음"
          ↓
  보수적 판단 원칙(소수 경고 우선 채택) → 검토 필요 판정
```

**패턴 3: 순차 정제**

첫 번째 서브에이전트 결과를 두 번째 서브에이전트가 개선하고 세 번째가 검증합니다.

```
[Researcher] 자료 수집 → [Writer] 초안 작성 → [Reviewer] 검토
```

이 패턴은 의존성이 있으므로 순차 실행입니다. 앞 단계 결과 전체를 다음 에이전트의 위임 프롬프트에 포함해야 합니다.

### 보안 주의: 프롬프트 인젝션

v2.1.210 이후 Claude Code는 서브에이전트가 반환하는 최종 보고서를 자동 스캔해서 프롬프트 인젝션 시도를 중화합니다(의심 구간에 역슬래시 삽입). 웹 페이지나 파일 내용처럼 외부 소스를 다루는 서브에이전트에서 이 보호가 작동합니다.

> 🔀 **네이티브 vs 팀 (연결)**: 8-3(업무 분담 전략)에서는 네이티브 병렬화가 한계에 부딪히는 규모 임계 기준을 대비 콜아웃으로 다룹니다. 이 절에서 배운 동시성 한계(기본 20개)가 그 임계의 첫 신호입니다.
