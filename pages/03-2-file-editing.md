## 03-2. 파일 읽기·편집 워크플로우

Claude Code의 진짜 강점은 "말로 설명하면 파일을 직접 고쳐 준다"는 데 있습니다. 이 절에서 익힐 것은 그 사이클 하나입니다 — **편집 지시 → diff 확인 → 승인 또는 거부 → 필요하면 되돌리기**. 이 리듬을 손에 익히면 코드 수정부터 문서 정리까지 일상 작업 대부분을 Claude Code로 처리할 수 있습니다.

> **이 페이지 범위**: 파일 읽기 요청 → 편집 지시 → diff 읽는 법 → 승인/거부 → 되돌리기(git·`/undo`) → 멀티파일 편집 감각. 권한 모드·도구 승인 세부는 03-5, CLAUDE.md로 편집 지침을 고정하는 방법은 03-6에서 다룹니다.

아래는 이 페이지에서 익힐 전체 흐름입니다.

```
파일 읽기 요청
       │
       ▼
 편집 지시 입력
       │
       ▼
 Claude가 diff 제안
       │
       ├─ 승인(y / Enter) → 파일에 반영
       │
       └─ 거부(n) → 변경 없음
              │
              ▼
          (이미 반영된 경우) git restore 또는 /undo
```

<hr>

## 파일 읽기 — 먼저 보여 달라고 하기

편집을 지시하기 전에 Claude에게 파일 내용을 먼저 보여 달라고 하면 어떤 파일을 다루는지 확인할 수 있습니다.

```
> src/main.py 파일 내용을 보여줘
```

Claude는 `Read` 도구로 파일을 읽은 뒤 내용을 출력합니다. [검증필요: 도구 이름·표시 방식]

```
src/main.py 파일 내용입니다:

def greet(name):
    print("Hello " + name)

greet("world")
```

여러 파일을 함께 보고 싶을 때도 자연어로 요청하면 됩니다.

```
> src/ 디렉터리 아래 파이썬 파일을 모두 읽어서 구조를 설명해줘
```

> 💡 편집을 맡기기 전에 "이 파일에 뭐가 있어?"를 먼저 물어보는 습관을 들이면 좋습니다. Claude가 어느 파일을 읽었는지 확인할 수 있어서, 예상 밖의 파일이 수정되는 상황을 줄일 수 있습니다.

<hr>

## 편집 지시하기

파일을 확인했다면 원하는 변경을 자연어로 지시합니다.

```
> greet 함수가 이름 뒤에 느낌표를 붙이도록 수정해줘
```

Claude가 수정안을 만든 뒤 **diff 형식**으로 변경 내용을 보여주며 확인을 요청합니다. [검증필요: 승인 UI 정확한 표시 방식]

```
src/main.py 파일을 수정하겠습니다:

  def greet(name):
-     print("Hello " + name)
+     print("Hello " + name + "!")
  
  greet("world")

이 변경을 적용하시겠습니까? (y/n)
```

`-`로 시작하는 줄은 **삭제될 내용**, `+`로 시작하는 줄은 **추가될 내용**, 앞에 아무 기호가 없는 줄은 **그대로 유지되는 맥락 줄**입니다.

<hr>

## diff 읽는 법

diff 표시는 처음에는 낯설지만 패턴을 알면 금방 익숙해집니다.

**기본 기호**:

| 기호 | 의미 |
|---|---|
| `-` (빨간색) | 이 줄은 삭제됩니다 |
| `+` (초록색) | 이 줄이 새로 추가됩니다 |
| ` ` (공백, 흰색) | 변경 없음 — 위치 파악용 맥락 |

**예시 — 함수 이름 변경**:

```diff
- def greet(name):
+ def say_hello(name):
      print("Hello " + name + "!")
  
- greet("world")
+ say_hello("world")
```

위 diff를 읽으면: 함수 이름이 `greet`에서 `say_hello`로 바뀌고, 호출부도 함께 바뀐다는 것을 알 수 있습니다. 맥락 줄(공백으로 시작)은 실제로 수정되지 않습니다.

**여러 위치가 수정될 때**: diff가 여러 묶음(헝크, hunk)으로 나뉘어 표시됩니다. `@@ -10,5 +10,5 @@` 같은 줄은 "원본 파일 10번 줄 근처"를 가리킵니다. [검증필요: 터미널 컬러·헝크 표시 방식]

> ⚠️ **흔한 실수**: diff를 훑어볼 때 `+` 줄만 확인하고 `-` 줄을 건너뛰는 경우가 있습니다. **삭제되는 줄**을 빠뜨리면 의도치 않은 코드가 사라질 수 있으니, `-` 줄도 반드시 확인하세요.

<hr>

## 승인과 거부

diff를 확인한 뒤 적용 여부를 결정합니다.

**승인**: `y`를 입력하거나 Enter를 누릅니다. [검증필요: 기본 키 동작]

```
이 변경을 적용하시겠습니까? (y/n) y
✓ src/main.py 수정 완료
```

**거부**: `n`을 입력하면 파일은 변경되지 않습니다.

```
이 변경을 적용하시겠습니까? (y/n) n
변경이 취소되었습니다.

>
```

거부 후에는 프롬프트로 돌아옵니다. 다른 지시를 입력하거나 같은 요청을 다시 수정해 보낼 수 있습니다.

```
> 느낌표 대신 쉼표를 붙여서 "Hello, name" 형식으로 바꿔줘
```

> 💡 확신이 없을 때는 일단 `n`으로 거부하고 Claude에게 "왜 그렇게 고쳤어?"라고 이유를 물어보세요. 의도를 설명해 주면 더 정확한 수정안을 다시 제안합니다.

<hr>

## 되돌리기 — 승인 후 취소하고 싶을 때

`y`로 승인해 파일에 반영했지만 결과가 마음에 들지 않을 때는 두 가지 방법으로 되돌릴 수 있습니다.

**방법 1 — `/undo` 슬래시 명령어**: 대화와 코드를 이전 체크포인트로 함께 롤백합니다. `/rewind`, `/checkpoint`과 동일한 명령입니다.

```
> /undo
✓ 이전 체크포인트로 롤백되었습니다.
```

> ⚠️ `/undo`는 **파일 편집만** 되돌리는 것이 아닙니다. 대화 이력도 함께 체크포인트 시점으로 되감깁니다. "방금 수정한 코드만 되돌리고 대화는 유지"하고 싶다면 `git restore`를 사용하세요.

**방법 2 — Git으로 되돌리기**: 프로젝트가 Git 저장소라면 `git restore`가 가장 확실합니다.

```bash
git diff                       # 현재 변경 내용 확인
git restore src/main.py        # 특정 파일만 되돌리기
git restore .                  # 모든 변경 파일을 되돌리기
```

> ⚠️ **흔한 실수**: `git restore .`는 승인한 Claude Code 편집뿐 아니라 **여러분이 직접 수정한 내용까지** 되돌립니다. 되돌리기 전에 `git diff`로 무엇이 바뀌어 있는지 먼저 확인하세요.

**어느 방법을 쓸까**:

| 상황 | 권장 방법 |
|---|---|
| 직전 편집 한 건만 취소 | `/undo` (빠르고 간편) |
| 여러 번 편집 후 특정 파일만 원복 | `git restore <파일>` |
| 세션 전체 변경을 처음으로 되돌리기 | `git checkout HEAD` 또는 `git stash` |

> 🔀 **Plan Mode(연결)**: 큰 리팩터링 전에 Claude가 먼저 계획을 세우고 승인받은 뒤 실행하게 하는 **Plan Mode**는 03-5에서 다룹니다. 실수를 줄이고 싶다면 Plan Mode를 먼저 활성화하는 것이 효과적입니다.

## 멀티파일 편집 — 여러 파일을 한 번에

Claude Code는 요청 하나로 여러 파일을 함께 수정할 수 있습니다.

```
> greet 함수 이름을 say_hello로 바꾸고, 이 함수를 쓰는 모든 파일에도 반영해줘
```

Claude가 관련 파일을 모두 찾아 각각의 diff를 보여줍니다.

```
src/main.py 수정:

- def greet(name):
+ def say_hello(name):

tests/test_main.py 수정:

- result = greet("world")
+ result = say_hello("world")

2개 파일을 수정합니다. 진행하시겠습니까? (y/n)
```

승인하면 두 파일이 한 번에 변경됩니다. [검증필요: 멀티파일 승인 UI 정확한 방식]

**멀티파일 편집 시 확인 포인트**:

1. **범위가 맞는가**: Claude가 수정하려는 파일 목록이 의도한 범위 안에 있는지 확인합니다.
2. **각 diff를 읽는가**: 파일이 여러 개라도 각 diff를 건너뛰지 마세요. 특히 테스트 파일·설정 파일 변경을 주의합니다.
3. **의존 관계 파악**: Claude는 함수 호출, import, 설정 등을 추적해 관련 파일을 찾습니다. 그래도 모든 파일을 발견하지 못할 수 있으므로, 변경 후 `git diff`로 전체 변경 내용을 한 번 더 확인하는 습관이 좋습니다.

> ⚠️ **흔한 실수**: 멀티파일 편집을 일괄 승인한 뒤 "생각보다 많은 파일이 바뀌었다"고 느끼는 경우가 있습니다. 처음에는 파일 1~2개씩 순서대로 맡기면서 Claude가 어떻게 변경을 파악하는지 감을 익히세요. 익숙해지면 범위를 넓혀도 됩니다.

<hr>

## 편집 후 확인 습관

변경을 승인했다면 두 가지를 확인하는 습관을 들이면 좋습니다.

**1. 파일 직접 열어보기**: Claude Code 밖에서 파일을 열어 실제로 수정이 의도한 대로 됐는지 눈으로 확인합니다.

**2. 테스트 실행**: 테스트 코드가 있다면 반드시 실행해 봅니다.

```
> 방금 수정한 뒤 테스트를 실행해줘
```

Claude가 터미널 명령을 실행해 테스트 결과를 보여줍니다. [검증필요: 쉘 명령 실행 승인 UI]

```bash
$ python -m pytest tests/
```

```
PASSED tests/test_main.py::test_greet - 1 passed in 0.12s
```

> 🔀 **권한 시스템(연결)**: Claude가 터미널 명령을 실행할 때는 별도 승인이 필요합니다. 어떤 명령에 어떤 권한이 요구되는지는 03-5(Plan Mode와 권한 시스템)에서 설명합니다.

## 정리

이 절에서 익힌 편집 사이클을 정리합니다.

```
파일 읽기 → 편집 지시 → diff 확인(- 삭제·+ 추가)
         → 승인(y) 또는 거부(n)
         → 필요하면 /undo 또는 git restore
```

파일 1개든 10개든 이 리듬은 같습니다. 다음 03-3에서는 `/help` `/clear` `/model` 같은 **슬래시 명령어**를 익혀서 세션 안에서 Claude Code를 더 능숙하게 제어하는 방법으로 넘어갑니다.
